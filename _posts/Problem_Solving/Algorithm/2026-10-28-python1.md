### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/42577)


### 문제 설명

전화번호부에 적힌 전화번호 중, 한 번호가 다른 번호의 접두어인 경우가 있는지 확인하려 합니다.
전화번호가 다음과 같을 경우, 구조대 전화번호는 영석이의 전화번호의 접두사입니다.

- 구조대 : 119
- 박준영 : 97 674 223
- 지영석 : 11 9552 4421

전화번호부에 적힌 전화번호를 담은 배열 phone_book 이 solution 함수의 매개변수로 주어질 때, 어떤 번호가 다른 번호의 접두어인 경우가 있으면 false를 그렇지 않으면 true를 return 하도록 solution 함수를 작성해주세요.



### 제한사항

- phone_book의 길이는 1 이상 1,000,000 이하입니다.
- 각 전화번호의 길이는 1 이상 20 이하입니다.
- 같은 전화번호가 중복해서 들어있지 않습니다.



### 입출력 예시

| phone_book | return |
| --- | --- |
| ["119", "97674223", "1195524421"] | false |
| ["123","456","789"] | true |
| ["12","123","1235","567","88"] | false |



### 내 풀이

```python
def solution(phone_book):
    phone_book.sort()
    for i in range(len(phone_book)-1):
        if phone_book[i] == phone_book[i+1][:len(phone_book[i])]:
            return False

    return True
```


### 코드 설명

길이가 100만이라 모든 쌍을 비교하면 O(n²)로 시간 초과가 난다. 그래서 **문자열 그대로 정렬**해서 바로 옆끼리만 비교했다.

문자열로 정렬하면 사전순이 되어서, 어떤 번호로 시작하는 번호는 그 번호 바로 뒤에 붙는다. 예시 1번을 정렬하면 `["119", "1195524421", "97674223"]`이 되어 `"119"`와 `"1195524421"`이 나란히 온다. 그래서 옆끼리만 봐도 접두어 관계를 놓치지 않는다.

- 시간: 정렬 O(n log n) + 옆끼리 비교 n번 → **O(n log n)**



### 다른 풀이

같은 방식을 더 짧게 쓰는 방법이다.

```python
def solution(phone_book):
    phone_book.sort()
    for a, b in zip(phone_book, phone_book[1:]):
        if b.startswith(a):
            return False
    return True
```

- `b.startswith(a)`: "b가 a로 시작하나?"를 바로 확인한다. `b[:len(a)] == a`와 같은 뜻인데 길이 계산을 직접 안 해도 된다
- `zip(리스트, 리스트[1:])`: **바로 옆끼리 짝 지을 때** 쓰는 방법. 인덱스 `i`, `i+1`을 안 써도 된다
- `startswith`는 앞 글자 몇 개만 비교하니까 O(앞부분 길이)다. 이 풀이가 O(n log n)인 건 `sort()` 때문이다

이 문제가 해시 분류에 있는 이유인 set 풀이도 있다.

```python
def solution(phone_book):
    s = set(phone_book)
    for num in phone_book:
        for i in range(1, len(num)):
            if num[:i] in s:
                return False
    return True
```

- 질문을 뒤집은 것이다. "어떤 번호가 다른 번호의 앞부분인가?" 대신 "**이 번호의 앞부분 중에 전화번호부에 있는 번호가 있나?**"를 번호마다 확인한다
- `"1195524421"`이면 `"1"`, `"11"`, `"119"`, ... 순서로 잘라서 set에 **정확히 같은 번호**가 있는지 본다. `"119"`에서 걸린다
- set은 중복을 없애려고 쓰는 게 아니라 **`in`을 O(1)로 빠르게 하려고** 쓴다. 리스트의 `in`은 처음부터 하나씩 비교해서 O(n)
- set은 "정확히 이 문자열이 있나?"만 확인할 수 있어서, 접두어가 몇 자리일지 모르니 가능한 길이를 전부 잘라 봐야 한다
- `range(1, len(num))`: 끝까지 자르면 자기 자신이 되고, 자기 자신은 당연히 set에 있으니 한 자리 전에서 멈춘다
- `"119"`를 뽑았을 때는 `"1"`, `"11"`만 보고 못 찾고 넘어가지만 괜찮다. 접두어 관계는 항상 **긴 번호 차례에서** 잡히고, 모든 번호를 한 번씩 다 뽑으니 놓치는 쌍이 없다
- 시간: 번호마다 최대 19번 조회 → O(n × 20). 이론상 O(n)이지만 log₂(100만)도 약 20이라 실제로는 정렬 풀이와 비슷하다



### 기록

- **모든 쌍 비교가 안 되면 정렬해서 옆끼리 비교**를 떠올리기. 비슷한 것끼리 붙는 문제에 쓴다
- 숫자처럼 생겼어도 **문자열로 정렬해야** 접두어가 붙는다
- 옆끼리 짝 짓기: `zip(a, a[1:])`. 접두어 확인: `startswith`
- set을 쓰는 이유는 중복 제거만이 아니라 **빠른 `in`**
- "길이 20 이하"처럼 **범위가 작게 주어지면 그걸 다 잘라 봐도 된다**는 신호
