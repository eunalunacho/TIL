### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/181855)


### 문제 설명

문자열 배열 strArr이 주어집니다. strArr의 원소들을 길이가 같은 문자열들끼리 그룹으로 묶었을 때 가장 개수가 많은 그룹의 크기를 return 하는 solution 함수를 완성해 주세요.



### 제한사항

- 1 ≤ strArr의 길이 ≤ 100,000
- 1 ≤ strArr의 원소의 길이 ≤ 30
- strArr의 원소들은 알파벳 소문자로 이루어진 문자열입니다.



### 입출력 예시

| strArr | result |
| --- | --- |
| ["a","bc","d","efg","hi"] | 2 |

각 문자열을 길이별로 묶으면 다음과 같다.

| 문자열 길이 | 문자열 목록 | 개수 |
| --- | --- | --- |
| 1 | ["a","d"] | 2 |
| 2 | ["bc","hi"] | 2 |
| 3 | ["efg"] | 1 |

개수의 최댓값은 2이므로 2를 return 한다.



### 내 풀이

```python
from collections import Counter

def solution(strArr):
    cnt = Counter(len(string) for string in strArr)

    return max(cnt.values())
```


### 코드 설명

문자열을 길이로 바꿔서 길이별 개수를 세고, 그중 가장 큰 개수를 반환한다.

- `Counter(...)`: 각 값이 몇 번 나왔는지 세서 `{값: 개수}` 형태로 만들어 준다. 예시에서는 `Counter({1: 2, 2: 2, 3: 1})`
- **`Counter`는 딕셔너리의 한 종류라 `.max()` 메서드가 없다.** 처음에 `cnt.max()`로 썼다가 막혔다. 개수만 꺼내서 `max(cnt.values())`로 써야 한다
- `max(cnt)`처럼 `.values()` 없이 쓰면 에러는 안 나지만 **키(길이) 중 가장 큰 값**이 나와서 답이 틀린다. 예시에서는 3이 나온다
- `Counter([...])`처럼 대괄호로 리스트를 만들 필요 없이 제너레이터(`len(string) for string in strArr`)를 바로 넘기면, 10만 개짜리 리스트를 따로 만들지 않아도 된다
- 시간: 한 번 훑으며 세므로 O(n)



### 다른 풀이

```python
from collections import Counter

def solution(strArr):
    return max(Counter(map(len, strArr)).values())
```

- `map(len, strArr)`는 `len(string) for string in strArr`와 같은 결과를 낸다. 함수 하나를 그대로 적용할 땐 `map`이 더 짧다

`most_common`을 쓰는 방법도 있다.

```python
from collections import Counter

def solution(strArr):
    return Counter(map(len, strArr)).most_common(1)[0][1]
```

- `most_common(1)`은 가장 많이 나온 항목 1개를 `[(키, 개수)]`로 준다. 예시에서는 `[(1, 2)]`
- `[0][1]`로 리스트의 첫 항목에서 개수를 꺼낸다. 인덱스가 두 번이라 `max(.values())`보다 읽기 어렵다
- 개수가 같은 항목이 여러 개여도 개수는 같으니 답에는 영향이 없다

문자열 길이가 **1~30**이라고 제한이 주어져 있어서, Counter 없이 리스트로 셀 수도 있다.

```python
def solution(strArr):
    cnt = [0] * 31
    for s in strArr:
        cnt[len(s)] += 1
    return max(cnt)
```

- 인덱스가 곧 문자열 길이라 `cnt[3]`이 "길이 3인 문자열의 개수"다. 길이가 최대 30이라 31칸을 만든다(0번 칸은 안 씀)
- 값의 범위가 작고 정해져 있으면 딕셔너리 대신 리스트로 세는 방법이 가능하다
- 시간은 같은 O(n)이고, import도 필요 없다. 그래도 Counter 풀이가 짧고 의도가 바로 보인다
- 네 풀이 모두 랜덤 입력 2만 개로 결과가 같은지 확인함



### 기록

- **Counter에서 최댓값 뽑기**
  - 가장 큰 개수: `max(cnt.values())`
  - 개수가 가장 큰 키: `max(cnt, key=cnt.get)`
  - (키, 개수) 쌍: `cnt.most_common(1)` → `[(키, 개수)]`
- `Counter`는 딕셔너리라서 `.max()`는 없다. `max(cnt)`는 개수가 아니라 키를 비교한다
- 길이가 정해진 값(여기선 1~30)을 셀 땐 **인덱스를 값으로 쓰는 리스트**도 방법이다
- 리스트 컴프리헨션 `[ ]`는 꼭 필요할 때만. 한 번만 훑을 거면 제너레이터나 `map`을 바로 넘기기
- 함수 하나를 모든 원소에 적용할 땐 `map(len, arr)`이 `len(x) for x in arr`보다 짧다
