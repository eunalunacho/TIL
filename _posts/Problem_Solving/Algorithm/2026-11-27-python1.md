### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/340199)


### 문제 설명

지폐를 접어서 지갑에 넣을 때, 최소 몇 번 접어야 하는지 구하는 문제다.

- 접을 때는 **항상 긴 쪽을 반으로** 접고, 홀수면 소수점 이하는 버린다
- 접힌 지폐를 **그대로 또는 90도 돌려서** 지갑에 넣을 수 있으면 그만 접는다
- 10 ≤ wallet[0], wallet[1] ≤ 100, 10 ≤ bill[0], bill[1] ≤ 2,000

| wallet | bill | result |
| --- | --- | --- |
| [30, 15] | [26, 17] | 1 |
| [50, 50] | [100, 241] | 4 |

예시 2는 `[100, 241] → [100, 120] → [100, 60] → [50, 60] → [50, 30]`으로 4번 접는다. 문제에 의사코드가 주어져 있어서 그대로 옮기면 풀리는 문제다.


### 내 풀이

```python
def solution(wallet, bill):
    answer = 0

    while min(wallet) < min(bill) or max(wallet) < max(bill):
        if bill[0] > bill[1]:
            bill[0] = bill[0] // 2
        else:
            bill[1] = bill[1] // 2

        answer += 1

    return answer
```


### 내 풀이 방식

**지갑에 들어갈 때까지 긴 쪽을 반으로 줄이며 횟수를 세는 시뮬레이션이다.**

- `min(wallet) < min(bill) or max(wallet) < max(bill)`: **지폐의 짧은 변이 지갑의 짧은 변보다 크거나, 긴 변이 지갑의 긴 변보다 크면** 아직 안 들어간다는 뜻이다. 각각 짧은 쪽끼리, 긴 쪽끼리 비교하면 "90도 돌려서 넣기"가 자동으로 처리된다
- `bill[0] > bill[1]`이면 `bill[0]`이 긴 쪽이라 반으로 줄이고, 아니면 `bill[1]`을 줄인다 (같으면 `bill[1]`)
- 예시 2(`wallet = [50, 50]`, `bill = [100, 241]`)를 따라가면 `[100, 241] → [100, 120] → [100, 60] → [50, 60] → [50, 30]`이다. 매번 `bill[0] > bill[1]`이면 `bill[0]`을, 아니면 `bill[1]`을 반으로 줄이고, 4번 접은 뒤 `min(wallet) = 50 < 30`도 `max(wallet) = 50 < 50`도 아니라서 끝난다

**복잡도**

- 시간: 한 번 접을 때마다 긴 변이 절반이 되므로 **O(log(지폐 크기))**. 이 문제의 최대 입력(지갑 10 × 10, 지폐 2,000 × 2,000)에서도 **16번**이면 끝난다 (직접 확인). 입력 크기 제한이 작아서 사실상 상수
- 공간: 변수 몇 개뿐이라 **O(1)**
- 정답 확인: 랜덤 입력 10만 개에서 아래 최적 풀이와 결과가 같고, 예시도 1, 4가 나온다

**하지만 입력 `bill`이 호출한 쪽에서도 바뀐다.**

`bill[0] = bill[0] // 2`는 리스트를 그 자리에서 바꾸는 코드라서, 함수에 넘긴 리스트가 같이 바뀐다.

```python
bill = [100, 241]
solution([50, 50], bill)
print(bill)         # [50, 30]   ← 넘긴 원본이 접힌 크기로 바뀌어 있다
```

프로그래머스는 케이스마다 새 입력으로 함수를 한 번씩 부르기 때문에 통과에는 문제가 없다. 하지만 실제 코드에서 같은 `bill`을 이어서 쓰면 원본이 망가진 채로 쓰게 된다. 앞의 [정사각형으로 만들기]에서 본 것과 같은 문제다.


### 최적 풀이

**방식은 같고(시뮬레이션), 입력을 건드리지 않고 "작은 쪽 / 큰 쪽"을 변수로 분리해서 코드를 단순하게 만든 것이다.**

```python
def solution(wallet, bill):
    w_small, w_large = sorted(wallet)       # 지갑: 짧은 변, 긴 변
    b_small, b_large = sorted(bill)         # 지폐: 짧은 변, 긴 변

    answer = 0
    while b_small > w_small or b_large > w_large:
        b_large //= 2                       # 항상 긴 변을 반으로 접는다
        b_small, b_large = min(b_small, b_large), max(b_small, b_large)   # 접은 뒤 짧은 변/긴 변을 다시 정한다
        answer += 1

    return answer
```

예시 2(`wallet = [50, 50]`, `bill = [100, 241]`)로 따라가면 이렇다.

- 시작: `w_small = 50`, `w_large = 50`, `b_small = 100`, `b_large = 241`
- 1번: `b_large = 241 // 2 = 120`. `min(100, 120) = 100`, `max(100, 120) = 120`이라 `(b_small, b_large) = (100, 120)`
- 2번: `b_large = 120 // 2 = 60`. `min(100, 60) = 60`, `max(100, 60) = 100`이라 `(60, 100)`. 긴 변이 바뀐 것을 `min/max`가 정리해 준다
- 3번: `b_large = 100 // 2 = 50`. `min(60, 50) = 50`, `max(60, 50) = 60`이라 `(50, 60)`
- 4번: `b_large = 60 // 2 = 30`. `min(50, 30) = 30`, `max(50, 30) = 50`이라 `(30, 50)`
- `30 > 50`도 `50 > 50`도 아니라서 끝난다. 답은 4

**내 풀이와 다른 점**

| | 내 풀이 | 최적 풀이 |
| --- | --- | --- |
| 시간 | O(log 크기), 최대 16번 | O(log 크기), 같음 |
| 공간 | O(1) | O(1), 같음 |
| 입력 `bill` | **바뀐다** | 바뀌지 않는다 (`sorted`가 새 리스트를 만든다) |
| 반복마다 하는 일 | `min`/`max`를 4번 호출, `if/else`로 어느 변인지 판단 | 정렬은 처음 한 번, 반복마다 `//=`와 `min/max` 한 쌍 |
| 조건식 | `min(wallet) < min(bill) or max(wallet) < max(bill)` | `b_small > w_small or b_large > w_large` |

**시간·공간 복잡도는 똑같다.** 입력이 이렇게 작으면 둘 다 몇 µs에 끝난다. 직접 재 보니 최악 입력에서 내 풀이는 약 2.9µs, 최적 풀이는 약 1.6µs였다. 큰 차이는 아니다.

**차이는 코드 복잡도(읽기 쉬움)다.**

1. **변 이름이 의미를 가진다.** 내 풀이는 `bill[0]`과 `bill[1]` 중 어느 쪽이 긴 쪽인지 매번 `if`로 확인해야 한다. 최적 풀이는 `b_large`가 항상 긴 변이라 `b_large //= 2` 한 줄로 "긴 쪽을 반으로 접는다"가 된다
2. **조건식이 그대로 읽힌다.** `b_small > w_small or b_large > w_large`는 "짧은 변이나 긴 변 중 하나라도 지갑보다 크면 접는다"로 읽힌다. `min(wallet) < min(bill)`은 부등호 방향이 거꾸로라서 한 번 더 생각해야 한다
3. **`if/else`가 없어진다.** 분기가 없어서 어느 경우를 빠뜨렸는지 따질 필요가 없다. 대신 접은 뒤 `min`/`max`로 다시 정렬하는 줄이 하나 늘어난다
4. **입력을 바꾸지 않는다.** `sorted`가 새 리스트를 돌려주므로 `wallet`, `bill`은 그대로다

정답 확인: 랜덤 입력 10만 개(지갑 10~100, 지폐 10~2,000)에서 두 풀이의 답이 같고, 최적 풀이는 입력 `bill`이 바뀌지 않음도 확인했다.


### 내가 놓친 것

- **풀이는 맞았다. 이번에 놓친 것은 입력 리스트를 직접 바꾸는 습관이다.** `bill[0] = ...`처럼 인자로 받은 리스트를 바꾸면 호출한 쪽도 바뀐다. 접은 크기를 새 변수에 담아서 쓰면 안전하다
- **"작은 쪽 / 큰 쪽" 비교는 `sorted`로 한 번 정리하고 시작한다.** 90도 돌려 넣을 수 있다는 조건이 "짧은 변은 짧은 변끼리, 긴 변은 긴 변끼리 비교"로 바뀌어서, 가로/세로를 따로 신경 쓰지 않아도 된다
- **반복마다 `min`/`max`를 여러 번 부르고 있으면 한 번만 계산해서 변수로 둘 수 있는지 본다**
- 반으로 줄이는 반복은 **O(log n)**이다. 한 번에 절반이 되니 입력이 2배가 되어도 반복은 1번만 늘어난다
- 문제에 의사코드가 있으면 그대로 옮겨도 정답이다. 시간을 아끼려면 의사코드의 조건을 먼저 정확히 읽는다
