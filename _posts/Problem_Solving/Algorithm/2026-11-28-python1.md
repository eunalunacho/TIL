### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/250137)


### 문제 설명

붕대 감기 기술은 **t초 동안 1초마다 x만큼 체력을 회복하고, t초 연속으로 성공하면 y만큼 추가로 회복**한다. 최대 체력(`health`)을 넘을 수 없다.

- 몬스터에게 공격당하면 그 순간에는 회복하지 못하고, 연속 성공 시간이 0으로 초기화된다
- 공격당해서 체력이 0 이하가 되면 죽고, 이때 -1을 반환한다
- 모든 공격이 끝난 직후의 남은 체력을 반환한다
- 1 ≤ t ≤ 50, 1 ≤ x, y ≤ 100, 1 ≤ health ≤ 1,000, 1 ≤ attacks의 길이 ≤ 100, 공격 시간 ≤ 1,000
- attacks는 공격 시간 오름차순이고, 공격 시간은 모두 다르다

| bandage | health | attacks | result |
| --- | --- | --- | --- |
| [5, 1, 5] | 30 | [[2, 10], [9, 15], [10, 5], [11, 5]] | 5 |
| [3, 2, 7] | 20 | [[1, 15], [5, 16], [8, 6]] | -1 |
| [4, 2, 7] | 20 | [[1, 15], [5, 16], [8, 6]] | -1 |
| [1, 1, 1] | 5 | [[1, 2], [3, 2]] | 3 |


### 내 풀이

```python
def solution(bandage, health, attacks):
    hp = health
    t, x, y = bandage

    before = 0
    for attack in attacks:
        if (attack[0] - before - 1) >= t:
            hp += x * (attack[0] - before - 1) + y * ((attack[0] - before - 1) // t)
        else:
            hp += x * (attack[0] - before - 1)
        if hp > health:
            hp = health

        hp = hp - attack[1]
        before = attack[0]

        if hp <= 0:
            return -1

    return hp
```


### 내 풀이 방식

**1초씩 시간을 흘려보내지 않고, "공격과 공격 사이의 빈 구간"을 한 번에 계산한다.**

- `attack[0] - before - 1`: 이전 공격과 이번 공격 사이에 붕대를 감을 수 있는 **초 수**(`gap`)다. 공격이 일어나는 초에는 회복이 없어서 1을 뺀다. 첫 공격 전은 `before = 0`에서 시작
- 그 구간의 회복량은 `x * gap`(초당 회복) + `y * (gap // t)`(t초 연속 성공을 `gap // t`번 완성한 만큼의 추가 회복)이다
- 회복한 뒤 `health`를 넘으면 `health`로 자르고, 그다음 이번 공격의 피해량을 뺀다. 0 이하이면 바로 -1

예시 1(`[5, 1, 5]`, `health = 30`)을 따라가 보면 이렇다.

- 공격 `[2, 10]`: `gap = 2 - 0 - 1 = 1`, 회복 `1 * 1 = 1`이라 31이지만 30으로 자르고, `30 - 10 = 20`
- 공격 `[9, 15]`: `gap = 9 - 2 - 1 = 6`, `6 >= 5`라서 회복 `1 * 6 + 5 * (6 // 5) = 11`, 31이지만 30으로 자르고, `30 - 15 = 15`
- 공격 `[10, 5]`: `gap = 0`, 회복 없음, `15 - 5 = 10`
- 공격 `[11, 5]`: `gap = 0`, `10 - 5 = 5`
- 정답은 5

**복잡도**

- 시간 **O(m)**: `m`은 `attacks`의 길이(≤ 100). 공격마다 몇 번의 사칙연산만 한다
- 공간 **O(1)**: 변수 몇 개뿐

**처음 제출은 일부 실패했다.** 추가 회복을 `y`로 **한 번만** 더했기 때문이다. 공격 사이가 `t`초의 2배, 3배 이상으로 길면 연속 성공을 여러 번 완성하는데 한 번만 더했다.

```python
bandage = [1, 5, 5]
health = 60
attacks = [[1, 17], [4, 29]]
```

- 첫 공격: `gap = 0`, `60 - 17 = 43`
- 두 번째 공격 전 `gap = 4 - 1 - 1 = 2`, `t = 1`이라 **연속 성공을 2번 완성**한다
- 맞는 계산: `43 + 5 * 2 + 5 * (2 // 1) = 63` → 60으로 자르고 `60 - 29 = 31`
- 처음 코드: `43 + 5 * 2 + 5 = 58`, `58 - 29 = 29` (추가 회복을 한 번만 더함)

`y * (gap // t)`로 고쳐서 해결했다. 랜덤 입력 5만 개에서 1초씩 흘려보내는 시뮬레이션과 결과가 같다.


### 정석 풀이 (1초씩 시뮬레이션)

**문제 설명 그대로 1초씩 시간을 보내며 체력과 연속 성공 횟수를 갱신한다.**

```python
def solution(bandage, health, attacks):
    t, x, y = bandage
    hp = health
    streak = 0                                   # 연속 성공 시간
    damage = dict(attacks)                       # {공격 시간: 피해량}

    for sec in range(1, attacks[-1][0] + 1):
        if sec in damage:
            hp -= damage[sec]
            streak = 0                           # 공격당하면 연속 성공 초기화
            if hp <= 0:
                return -1
        else:
            hp = min(health, hp + x)             # 1초 회복
            streak += 1
            if streak == t:
                hp = min(health, hp + y)         # t초 연속 성공 → 추가 회복
                streak = 0

    return hp
```

- 시간 **O(T)**: `T`는 마지막 공격 시간(≤ 1,000). 1초마다 한 번 돈다
- 공간 **O(m)**: 공격 시간을 키로 하는 딕셔너리

문제 설명 표와 코드가 그대로 대응해서 **틀리기 가장 어렵다.** 입력이 이렇게 작으면 이 풀이로도 충분히 통과한다. 위 정답의 비교 기준으로도 이 풀이를 썼다.


### 최적 풀이

**내 풀이와 방식은 같고, 코드의 반복과 분기를 없앤 것이다.**

```python
def solution(bandage, health, attacks):
    t, x, y = bandage
    hp = health
    prev = 0                                     # 직전 공격 시간 (처음에는 0)

    for time, damage in attacks:
        gap = time - prev - 1                    # 공격 사이에 붕대를 감는 시간
        hp = min(health, hp + x * gap + (gap // t) * y)
        hp -= damage
        if hp <= 0:
            return -1
        prev = time

    return hp
```

예시 1로 확인하면 이렇다.

- `[2, 10]`: `gap = 1`, `min(30, 30 + 1 + 0) = 30`, `30 - 10 = 20`
- `[9, 15]`: `gap = 6`, `min(30, 20 + 6 + 1 * 5) = 30`, `30 - 15 = 15`
- `[10, 5]`, `[11, 5]`: `gap = 0`이라 `15 - 5 = 10`, `10 - 5 = 5`
- 정답은 5

**내 풀이와 다른 점**

1. **`if gap >= t / else` 분기가 필요 없다.** `gap < t`이면 `gap // t`가 0이라서 `(gap // t) * y`가 자동으로 0이 된다. 분기 없이 한 식으로 쓸 수 있다
2. **`attack[0] - before - 1`을 한 번만 계산해서 `gap`에 담는다.** 내 풀이는 같은 식을 다섯 번 썼다
3. **`if hp > health: hp = health`를 `min(health, ...)`로 줄였다**
4. **`for time, damage in attacks`로 바로 풀어서 받는다.** `attack[0]`, `attack[1]`이 `time`, `damage`로 읽힌다

**복잡도 비교**

| | 시간 | 공간 | 비고 |
| --- | --- | --- | --- |
| 정석(1초 시뮬레이션) | O(T) | O(m) | T = 마지막 공격 시간 |
| 내 풀이 | O(m) | O(1) | |
| 최적 풀이 | O(m) | O(1) | 내 풀이와 같음 |

- **내 풀이와 최적 풀이는 시간·공간 복잡도가 같다.** 이미 O(m) / O(1)이라서 더 줄일 방법이 없다 (공격을 한 번씩은 읽어야 한다)
- **정석 풀이보다는 확실히 좋다.** 시뮬레이션은 시간이 흐른 만큼 반복하지만, 공격 사이를 수식으로 한 번에 계산하면 **공격의 개수만큼만** 반복한다
- 직접 재 보니 공격이 마지막 1,000초에 하나뿐인 입력에서 시뮬레이션은 약 151µs, 내 풀이와 최적 풀이는 약 0.5µs였다. 공격이 100개이고 10초 간격인 입력에서는 시뮬레이션 약 141µs, 내 풀이 약 22.2µs, 최적 풀이 약 22.0µs였다
- 내 풀이와 최적 풀이는 **속도 차이가 없다.** 최적 풀이가 나은 점은 속도가 아니라 **읽기 쉬움**이다 (분기와 반복된 식이 없다)

정답 확인: 문제 예시 4개(5, -1, -1, 3)와 랜덤 입력 5만 개에서 세 풀이의 결과가 같다.


### 내가 놓친 것

- **"t초 연속 성공할 때마다"는 한 번이 아니라 `gap // t`번이다.** `gap >= t`이면 한 번만 더하는 식은 `gap`이 `2t`를 넘는 순간부터 틀린다. 문제의 "한 번"이 반복 규칙인지 한 번만인지 예시로 확인한다
- **조건 분기가 "`gap // t`가 0이면 자동으로 0이 된다"로 없어지는지 먼저 본다.** 경계 조건을 `if`로 나누기 전에 식이 알아서 처리하는지 확인한다
- **같은 식을 여러 번 쓰면 변수 하나로 묶는다** (`gap`)
- **상한(최대 체력)은 마지막에 한 번 `min`으로 자르면 된다.** 이번처럼 회복이 줄어들지 않고 늘기만 하는 경우에는 중간에 자르든 마지막에 자르든 결과가 같다
- **시간이 흐르는 문제는 "1초씩 시뮬레이션"이 기준이다.** 시간이 길거나 이벤트가 드문 문제에서는 이벤트와 이벤트 사이를 수식으로 한 번에 계산한다
- 디버깅용 `print`(이번에는 `print("Gap:", ...)`)는 제출 전에 지우기
- 실패한 케이스를 모를 때는 **정석 시뮬레이션과 랜덤 비교**를 하면 원인이 바로 보인다 (이번에도 이렇게 반례를 찾았다)
