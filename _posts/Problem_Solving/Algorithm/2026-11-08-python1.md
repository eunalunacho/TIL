### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/181846)


### 문제 설명

0 이상의 두 정수가 문자열 a, b로 주어질 때, a + b의 값을 문자열로 return 하는 solution 함수를 작성해 주세요.



### 제한사항

- 1 ≤ a의 길이 ≤ 100,000
- 1 ≤ b의 길이 ≤ 100,000
- a와 b는 숫자로만 이루어져 있습니다.
- a와 b는 정수 0이 아니라면 0으로 시작하지 않습니다.



### 입출력 예시

| a | b | result |
| --- | --- | --- |
| "582" | "734" | "1316" |
| "18446744073709551615" | "287346502836570928366" | "305793246910280479981" |
| "0" | "0" | "0" |



### 내 풀이

```python
def solution(a, b):
    ans = []
    if len(a) > len(b):
        b = "0" * (len(a) - len(b)) + b
    elif len(b) > len(a):
        a = "0" * (len(b) - len(a)) + a

    tmp = 0
    for num_a, num_b in zip(a[::-1], b[::-1]):
        sm = int(num_a) + int(num_b) + tmp
        tmp = 0

        if sm >= 10:
            tmp += 1
        ans += [str(sm%10)]
    if tmp:
        ans += [str(tmp)]

    return ''.join(ans[::-1])
```


### 코드 설명

종이로 더하듯이 **끝자리부터 한 자리씩 더하고, 10 이상이면 올림(carry)을 다음 자리로 넘긴다.**

- 길이가 다르면 짧은 쪽 앞에 `"0"`을 채워 길이를 맞춘다
- `a[::-1]`, `b[::-1]`로 뒤집어서 일의 자리부터 `zip`으로 짝지어 돈다
- 한 자리 합(`sm`)에 이전 올림(`tmp`)을 더하고, `sm % 10`을 결과에 쌓고 `sm >= 10`이면 다음 올림을 1로 한다
- 다 돈 뒤에도 올림이 남으면 맨 앞에 붙인다 (예: 99 + 1 = 100)
- 결과 자릿수는 일의 자리부터 쌓였으므로 마지막에 `[::-1]`로 뒤집어서 `join`
- `"0" + "0"`은 반복 한 번으로 `"0"`이 나오고 올림이 없어 그대로 `"0"`이다
- 시간: 자릿수만큼 한 번씩 돌아서 O(n)

**처음엔 `str(int(a) + int(b))`로 풀었다가 16점을 받았다.**

- 파이썬 `int`는 자릿수 제한 없이 큰 수를 다루지만, **문자열 ↔ 정수 변환에는 자릿수 제한**이 있다. 파이썬 3.11 이상은 기본 4300자리이고, 넘으면 `ValueError`
- 이 문제는 최대 100,000자리라서 큰 테스트 케이스에서 막힌 것으로 추정된다 (채점 화면의 에러 메시지를 직접 확인한 것은 아님)
- 이진수로 바꾸는 방법은 해결책이 아니다. 어차피 문자열과 정수를 오가야 해서 같은 제한에 걸린다
- 그래서 **문자열 그대로 자릿수별로 더하는** 방식으로 바꿨다



### 다른 풀이

내 풀이는 정답이고 속도도 충분하다. 코드를 줄이는 방향과 더 빠르게 하는 방향 두 가지를 정리했다.

**1. `divmod`와 `zip_longest`로 정리하기**

```python
from itertools import zip_longest

def solution(a, b):
    res, carry = [], 0
    for x, y in zip_longest(reversed(a), reversed(b), fillvalue="0"):
        carry, d = divmod(int(x) + int(y) + carry, 10)
        res.append(str(d))
    if carry:
        res.append("1")
    return "".join(reversed(res))
```

- `divmod(합, 10)`은 `(몫, 나머지)`를 한 번에 준다. 몫이 곧 올림(0 또는 1), 나머지가 이번 자리의 숫자다. `tmp = 0`으로 초기화하고 `if sm >= 10`으로 나누던 부분이 한 줄로 줄어든다
- `zip_longest(..., fillvalue="0")`은 짧은 쪽을 자동으로 `"0"`으로 채워서 **앞에 0을 붙이는 코드가 필요 없다**
- `reversed(a)`는 문자열을 복사하지 않고 거꾸로 훑는 반복자다
- 올림이 남았을 때 `"1"`을 붙이는 이유: 한 자리 두 수와 올림의 합은 최대 9 + 9 + 1 = 19라서 올림은 항상 0 또는 1이다
- **줄었을 뿐 더 빠르진 않다.** 직접 재 보니 내 풀이보다 오히려 약간 느렸다 (아래 표). `zip_longest`가 튜플을 만드는 비용 때문으로 보인다

**2. 문자 코드로 계산해서 `int()` 호출 줄이기**

```python
def solution(a, b):
    n = max(len(a), len(b))
    a, b = a.zfill(n), b.zfill(n)
    res, carry = [], 0
    for i in range(n - 1, -1, -1):
        carry, d = divmod(ord(a[i]) + ord(b[i]) - 96 + carry, 10)
        res.append(chr(48 + d))
    if carry:
        res.append("1")
    return "".join(reversed(res))
```

- `zfill(n)`: 앞을 `0`으로 채워 길이 n으로 만든다. `"58".zfill(5)` → `"00058"`
- `ord('7')`은 55, `ord('0')`은 48. 두 문자의 코드를 더하면 48이 두 번 들어가므로 `- 96`을 하면 숫자의 합이 된다
- 반대로 `chr(48 + d)`는 숫자 d를 문자로 바꾼다
- `int()`와 `str()` 호출이 사라져서 조금 빠르지만, 읽기는 어려워진다

**3. 9자리씩 묶어서 더하기 (가장 빠름)**

```python
def solution(a, b, K=9):
    n = max(len(a), len(b))
    n += (-n) % K
    a, b = a.zfill(n), b.zfill(n)
    base = 10 ** K
    res, carry = [], 0
    for i in range(n, 0, -K):
        carry, s = divmod(int(a[i-K:i]) + int(b[i-K:i]) + carry, base)
        res.append(str(s).zfill(K))
    if carry:
        res.append(str(carry))
    return "".join(reversed(res)).lstrip("0") or "0"
```

- 한 자리씩이 아니라 **9자리씩 잘라서 정수로 바꿔 더한다.** 9자리는 `int` 변환 제한(4300자리)과 한참 거리가 멀다. 반복 횟수가 약 9분의 1로 줄어든다
- `n += (-n) % K`: n을 9의 배수로 올림해서 `zfill`로 채운다 (n = 10이면 18)
- 합이 10억 이상이면 `divmod(…, 10**9)`의 몫이 올림이 된다. 나머지는 `zfill(9)`로 9자리를 맞춰 붙인다 (이 단계에서 앞을 0으로 채우지 않으면 중간 자릿수가 사라진다)
- 앞에 붙인 0 때문에 맨 앞에 0이 남을 수 있어서 `lstrip("0")`로 지우고, 전부 0이면 `"0"`을 반환한다
- 자릿수를 청크 단위로 처리한다는 점에서 큰 수 곱셈, 해시 계산 같은 곳에서도 쓰는 방식이다

**속도 비교** (99…9가 10만 자리인 두 수를 더함, 내 컴퓨터, 파이썬 3.14)

| 방식 | 시간 |
| --- | --- |
| 내 풀이 | 약 34ms |
| `divmod` + `zip_longest` | 약 44ms |
| 문자 코드 | 약 22ms |
| 9자리씩 묶기 | 약 9ms |
| (참고) `str(int(a) + int(b))` 제한을 푼 경우 | 약 89ms |

- 일회성 측정이라 순위만 참고. 채점은 모든 방식이 충분히 빠르다
- 기본 풀이에서도 좋아진 게 많지는 않아서, **코드를 줄이려는 최적화인지 속도를 내려는 최적화인지** 목적을 정하고 고르는 게 낫다
- 네 풀이 모두 랜덤 입력 2만 쌍(0, 99…9, 길이가 다른 경우 포함)에서 `str(int(a) + int(b))`와 결과가 같은지 확인함

참고로 `sys.set_int_max_str_digits(0)`으로 변환 제한을 풀면 `str(int(a) + int(b))`도 통과할 수는 있지만, 3.11 이상에서만 있는 함수라서 채점 환경의 파이썬 버전에 따라 에러가 날 수 있다. 문제 의도는 자릿수별 계산이다.



### 기록

- **`int(문자열)`은 3.11부터 기본 4300자리 제한이 있다.** 파이썬 `int`가 큰 수를 못 다루는 게 아니라 문자열과의 변환에서 막힌다. 입력 길이가 10만 이상이면 문자열 그대로 처리하는 것을 먼저 생각하기
- **큰 수 덧셈은 끝자리부터 + 올림.** 두 수의 한 자리 합과 올림은 최대 9 + 9 + 1 = 19라서 올림은 0 또는 1
- 한 줄로 몫과 나머지를 구하기: `carry, d = divmod(합, 10)`. 올림 처리용 `if`와 변수 초기화가 줄어든다
- 길이가 다른 두 문자열은 `zfill(n)`(앞에 0 채우기) 또는 `zip_longest(..., fillvalue="0")`으로 맞춘다. `zip`은 짧은 쪽에 맞춰 끊긴다
- 뒤에서부터 쌓은 결과는 리스트에 `append`하고 마지막에 `"".join(reversed(res))`. 문자열 앞에 계속 붙이면 매번 복사해서 느리다
- 문자를 숫자로: `int('7')` 또는 `ord('7') - 48`. 숫자를 문자로: `str(7)` 또는 `chr(48 + 7)`
- 코드를 짧게 만든 게 항상 더 빠른 건 아니다. 최적화는 재 보고 판단하기 (이번 `zip_longest` 풀이는 오히려 느렸다)
- 변수 이름이 의미를 담아야 읽기 쉽다: `tmp` → `carry`
