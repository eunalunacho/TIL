### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/181883)


### 문제 설명

정수 배열 arr와 2차원 정수 배열 queries이 주어집니다. queries의 원소는 각각 하나의 query를 나타내며, [s, e] 꼴입니다.

각 query마다 순서대로 s ≤ i ≤ e인 모든 i에 대해 arr[i]에 1을 더합니다.

위 규칙에 따라 queries를 처리한 이후의 arr를 return 하는 solution 함수를 완성해 주세요.



### 제한사항

- 1 ≤ arr의 길이 ≤ 1,000
- 0 ≤ arr의 원소 ≤ 1,000,000
- 1 ≤ queries의 길이 ≤ 1,000
- 0 ≤ s ≤ e < arr의 길이



### 입출력 예시

| arr | queries | result | 
| --- | --- | --- |  
| [0, 1, 2, 3, 4] | [[0, 1],[1, 2],[2, 3]] | [1, 3, 4, 4, 4] |



### 내 풀이

```python
def solution(arr, queries):
    for query in queries:
        for i in range(len(arr)):
            if i >= query[0] and i <= query[1]:
                arr[i] += 1
    return arr
```


### 코드 설명

처음에 [s, e]를 값의 범위로 이해해서 `arr[i]`를 s, e와 비교했다가 틀렸다.
문제의 "s ≤ i ≤ e인 모든 i"는 arr의 위치(인덱스) 범위라서, 비교해야 하는 건 `arr[i]`가 아니라 `i`임

예시가 헷갈렸던 이유
1) 처음 arr가 [0, 1, 2, 3, 4]라 값과 인덱스가 우연히 같아서, 첫 쿼리까지는 두 해석의 결과가 같음
2) 입출력 예 설명 표의 i는 몇 번째 쿼리인지를 뜻하고, 문제 설명의 i는 arr의 몇 번째 칸인지를 뜻함. 둘은 서로 다른 i

쿼리 [0, 1]은 칸 하나가 아니라 arr의 0번 칸부터 1번 칸까지 구간 전체에 1을 더하라는 뜻



### 다른 풀이

**1) 구간만 돌기**

```python
def solution(arr, queries):
    for s, e in queries:
        for i in range(s, e + 1):
            arr[i] += 1
    return arr
```

- 내 풀이는 쿼리마다 arr 전체를 돌면서 i가 구간 안에 있는지 확인하지만, 이 풀이는 처음부터 s ~ e 칸만 돎
- `for s, e in queries`로 쿼리를 바로 풀어서 받으면 query[0], query[1]보다 읽기 쉬움
- 최악의 경우(모든 쿼리가 [0, n-1])는 내 풀이와 같은 O(q × n)이지만, 구간이 짧을수록 훨씬 적게 돎

**2) 차분 배열 (가장 빠른 풀이)**

```python
def solution(arr, queries):
    diff = [0] * (len(arr) + 1)
    for s, e in queries:
        diff[s] += 1
        diff[e + 1] -= 1

    add = 0
    for i in range(len(arr)):
        add += diff[i]
        arr[i] += add
    return arr
```

- 구간 전체에 1을 더하는 대신, 구간 시작 칸에 +1, 구간이 끝난 다음 칸에 -1만 표시해 둠
- 마지막에 앞에서부터 누적합을 구하면 각 칸에 더해질 값이 나옴
- 예시: 쿼리 [0,1], [1,2], [2,3] → diff = [1, 1, 0, -1, -1, 0] → 누적합 [1, 2, 2, 1, 0] → arr에 더하면 [1, 3, 4, 4, 4]
- 쿼리마다 2칸만 건드리고 마지막에 한 번만 훑으므로 O(n + q)
- 이 문제는 n, q가 최대 1,000이라 1)로도 충분하지만, n, q가 10만 이상이면 차분 배열이 필요함



### 기록

- 변수가 두 개면 복잡도도 두 개로 봄. 이 문제는 n²이 아니라 O(q × n) = 최악 1,000 × 1,000 = 100만 번
- 파이썬은 대략 1초에 1,000만 번 정도를 기준으로 잡음

| 최대 크기 | 가능한 복잡도 |
| --- | --- |
| ~ 1,000 | O(n²) 가능 |
| ~ 10,000 | O(n²)은 1억 번이라 위험 |
| ~ 100,000 | O(n log n) 또는 O(n)까지 |
| 1,000,000 이상 | O(n)이나 그 이하 |

- `0 ≤ arr의 원소 ≤ 1,000,000`은 값의 크기라 반복 횟수와 상관없음. 복잡도는 길이 제한을 보고 판단
