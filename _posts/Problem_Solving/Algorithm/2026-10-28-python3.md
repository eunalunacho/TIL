### 문제 설명

수많은 마라톤 선수들이 마라톤에 참여하였습니다. 단 한 명의 선수를 제외하고는 모든 선수가 마라톤을 완주하였습니다.

마라톤에 참여한 선수들의 이름이 담긴 배열 participant와 완주한 선수들의 이름이 담긴 배열 completion이 주어질 때, 완주하지 못한 선수의 이름을 return 하도록 solution 함수를 작성해주세요.



### 제한사항

- 마라톤 경기에 참여한 선수의 수는 1명 이상 100,000명 이하입니다.
- completion의 길이는 participant의 길이보다 1 작습니다.
- 참가자의 이름은 1개 이상 20개 이하의 알파벳 소문자로 이루어져 있습니다.
- 참가자 중에는 동명이인이 있을 수 있습니다.



### 입출력 예시

| participant | completion | return |
| --- | --- | --- |
| ["leo", "kiki", "eden"] | ["eden", "kiki"] | "leo" |
| ["marina", "josipa", "nikola", "vinko", "filipa"] | ["josipa", "filipa", "marina", "nikola"] | "vinko" |
| ["mislav", "stanko", "mislav", "ana"] | ["stanko", "ana", "mislav"] | "mislav" |



### 내 풀이 (다시 풀기)

```python
from collections import Counter

def solution(participant, completion):
    tmp = Counter(participant) - Counter(completion)
    return list(tmp)[0]
```


### 코드 설명

참가자와 완주자를 각각 Counter로 센 뒤 빼면, 완주 못 한 사람만 개수 1로 남는다. 동명이인도 개수로 세니까 자연스럽게 처리된다.

처음엔 결과에서 이름만 꺼내려고 `.keys()`를 썼는데 `dict_keys(['leo'])`처럼 나왔다. `keys()`는 리스트가 아니라 보기용 객체라서 `[0]`을 쓸 수 없다. **`list()`로 감싸야** 한다. Counter를 바로 `list(tmp)`로 바꿔도 키만 나온다.

- 시간: Counter 두 번 만들고 빼기 → **O(n)**



### 처음 풀이와 비교

처음 풀었을 때(2025-11-27)는 이렇게 풀었다.

```python
cnt = Counter(participant)

for name in completion:
    cnt[name] -= 1

for name, count in cnt.items():
    if count > 0:
        return name
```

| | 처음 풀이 | 다시 푼 풀이 |
| --- | --- | --- |
| 시간 | O(n) | O(n) |
| 장점 | 동작이 눈에 보이고, 다른 언어로도 같은 방식으로 풀 수 있다 | 짧고 실수할 곳이 적다 |

처음 풀이는 Counter를 하나만 만들어서 오히려 미세하게 더 빠를 수도 있지만, 10만 명 수준에서는 차이가 없다. 시험에서는 더 빨리, 덜 틀리게 쓸 수 있는 쪽을 고르면 된다.



### 다른 풀이

```python
from collections import Counter

def solution(participant, completion):
    return next(iter(Counter(participant) - Counter(completion)))
```

- `iter()`: 묶음을 **하나씩 꺼낼 수 있는 상태(이터레이터)** 로 바꾼다. `for` 문도 안에서 이걸 자동으로 한다
- `next()`: 이터레이터에서 **다음 것 하나**를 꺼낸다. 다 꺼냈는데 또 부르면 `StopIteration` 에러
- `next(iter(c))`는 리스트를 만들지 않고 첫 키 하나만 꺼낸다. 결과는 `list(c)[0]`과 같아서 남는 키가 하나뿐인 이 문제에서는 차이가 거의 없다



### 기록: Counter 정리

딕셔너리를 하나씩 꺼내면(`list(c)`, `for x in c`) 원래 **키만** 나온다. 값이 없어진 게 아니라 `c[키]`로 언제든 찾을 수 있어서 그렇다.

| 필요한 것 | 쓰는 것 |
| --- | --- |
| 키만 | `list(c)` 또는 `list(c.keys())` |
| 값만 | `list(c.values())` |
| 키와 값 쌍 | `list(c.items())`, `for k, v in c.items()` |
| 특정 키의 값 | `c[키]` (대괄호) |
| 첫 쌍 하나 | `next(iter(c.items()))` |

연산자 4개 (결과에서 0 이하인 키는 사라진다)

```python
a = Counter("aab")    # {'a': 2, 'b': 1}
b = Counter("abc")    # {'a': 1, 'b': 1, 'c': 1}

a + b    # {'a': 3, 'b': 2, 'c': 1}   개수 더하기
a - b    # {'a': 1}                   개수 빼기 (0·음수는 버림)
a & b    # {'a': 1, 'b': 1}           키마다 작은 쪽 개수
a | b    # {'a': 2, 'b': 1, 'c': 1}   키마다 큰 쪽 개수
```

자주 쓰는 메서드

```python
a.subtract("abc")    # 원본을 바꾸고 음수도 남김 → {'a': 1, 'b': 0, 'c': -1}
a.most_common(1)     # 가장 많은 것 → [('a', 2)]
list(a.elements())   # 개수만큼 풀어 놓기 → ['a', 'a', 'b']
a.update("bb")       # 원본에 개수 더하기
sum(a.values())      # 전체 개수 합
```

- 없는 키를 조회하면 에러 없이 0
- `a == b`로 구성이 같은지 바로 비교 (순서 상관없음)
- 남는 것만 필요하면 `-`, 부족한 것까지 알아야 하면 `subtract`
- `subtract` 후 0인 키도 남아서 `len()`에 들어간다. `+c`로 0 이하인 키를 지울 수 있다
