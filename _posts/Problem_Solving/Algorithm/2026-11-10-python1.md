### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/181832)


### 문제 설명

양의 정수 n이 매개변수로 주어집니다. n × n 배열에 1부터 n² 까지 정수를 인덱스 [0][0]부터 시계방향 나선형으로 배치한 이차원 배열을 return 하는 solution 함수를 작성해 주세요.



### 제한사항

- 1 ≤ n ≤ 30



### 입출력 예시

| n | result |
| --- | --- |
| 4 | [[1, 2, 3, 4], [12, 13, 14, 5], [11, 16, 15, 6], [10, 9, 8, 7]] |
| 5 | [[1, 2, 3, 4, 5], [16, 17, 18, 19, 6], [15, 24, 25, 20, 7], [14, 23, 22, 21, 8], [13, 12, 11, 10, 9]] |

n = 4일 때의 배열은 다음과 같다.

| 행 \ 열 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 0 | 1 | 2 | 3 | 4 |
| 1 | 12 | 13 | 14 | 5 |
| 2 | 11 | 16 | 15 | 6 |
| 3 | 10 | 9 | 8 | 7 |



### 내 풀이

```python
def solution(n):
    answer = [[0] * n for _ in range(n)]
    direct = [(0,1), (1,0), (0,-1), (-1,0)]
    d = 0
    r, c = 0, 0
    answer[0][0] = 1

    for i in range(2, n*n +1):
        dr, dc = direct[d]
        nr, nc = r + dr, c + dc
        if nr < 0 or nr >= n or nc >= n or answer[nr][nc] != 0:
            d = (d + 1) % 4
            dr, dc = direct[d]
            nr, nc = r + dr, c + dc

        answer[nr][nc] = i
        r, c = nr, nc

    return answer
```


### 코드 설명

한 칸씩 걸어가면서 숫자를 채우고, **벽이나 이미 채운 칸을 만나면 방향을 바꾸는** 시뮬레이션이다.

- `direct = [(0,1), (1,0), (0,-1), (-1,0)]`: `(행 변화, 열 변화)`로 **오른쪽 → 아래 → 왼쪽 → 위**. 시계방향 순서로 나열해 두면 방향을 바꿀 때 번호만 하나 올리면 된다
- `d = (d + 1) % 4`: 방향 번호를 하나 올리고, 4가 되면 0으로 돌아간다
- 0으로 칸을 미리 채워 둔 덕분에 `answer[nr][nc] != 0`이 "이미 채운 칸"을 뜻한다
- 방향을 바꾼 뒤에는 **새 방향으로 다음 칸을 다시 계산**한다. 방향을 바꿔도 다음 칸은 항상 비어 있다 (나선형이라 연속으로 두 번 막히지 않는다)
- 시간: 칸마다 한 번씩 O(n²)

**풀이하면서 막혔던 부분**

- **처음엔 튜플끼리 더하고 빼려고 했다.** `(0, 0) + (1, 0)`은 `(0, 0, 1, 0)`으로 이어 붙여지고, 빼기는 `TypeError`다. 좌표는 `r, c`와 `dr, dc`로 따로 변수로 풀어서 `r + dr`, `c + dc`로 계산해야 한다. `dr, dc = direct[d]`로 언패킹
- **`r = nr, c = nc`는 `r, c = nr, nc`가 아니다.** 연쇄 대입(`a = b = 0`)으로 읽혀서 `nc`(정수)를 `(nr, c)`로 풀려다가 `cannot unpack non-iterable int object`가 난다. 두 값을 한꺼번에 대입할 땐 쉼표로 묶는다
- 범위 검사에서 `nr >= n`처럼 인덱스의 끝은 `n - 1`임을 주의. `<= n`으로 쓰면 틀린다
- **`nc < 0` 검사가 빠져 있는데도 통과했다.** 아래 행에서 왼쪽으로 가다가 `nc = -1`이 되면 파이썬의 음수 인덱스 때문에 `answer[nr][-1]`(마지막 열)을 가리키고, 그 칸은 이미 채워져 있어서 우연히 `!= 0`에 걸렸다. 의도한 검사가 아니라서 아래 풀이에서는 `nc < 0`도 확인한다



### 다른 풀이

**1. 방향 이동 방식을 정리하기**

```python
def solution(n):
    answer = [[0] * n for _ in range(n)]
    directions = [(0, 1), (1, 0), (0, -1), (-1, 0)]
    d = 0
    r, c = 0, 0

    for num in range(1, n * n + 1):
        answer[r][c] = num
        nr, nc = r + directions[d][0], c + directions[d][1]
        if not (0 <= nr < n and 0 <= nc < n) or answer[nr][nc] != 0:
            d = (d + 1) % 4
            nr, nc = r + directions[d][0], c + directions[d][1]
        r, c = nr, nc

    return answer
```

- 숫자를 먼저 넣고 다음 칸을 계산하는 순서로 바꿔서, `answer[0][0] = 1`을 따로 쓰지 않고 `range(1, n*n+1)` 하나로 통일했다
- `0 <= nr < n and 0 <= nc < n`: 행과 열의 범위를 한 번에 검사한다. `nc < 0` 누락 같은 실수가 줄어든다
- `not (범위 안) or 이미 채움`으로 쓰는 순서가 중요하다. `or`는 앞이 참이면 뒤를 평가하지 않아서, 범위를 벗어났을 때 `answer[nr][nc]`를 접근하지 않는다
- 마지막 숫자를 넣은 뒤에도 다음 칸을 계산하지만 값을 넣지 않고 끝나므로 문제 없다

**2. 바깥 테두리부터 한 겹씩 채우기**

```python
def solution(n):
    answer = [[0] * n for _ in range(n)]
    top, bottom, left, right = 0, n - 1, 0, n - 1
    num = 1

    while top <= bottom and left <= right:
        for c in range(left, right + 1):          # 위쪽 행: 왼쪽 → 오른쪽
            answer[top][c] = num
            num += 1
        top += 1

        for r in range(top, bottom + 1):          # 오른쪽 열: 위 → 아래
            answer[r][right] = num
            num += 1
        right -= 1

        if top <= bottom:
            for c in range(right, left - 1, -1):  # 아래쪽 행: 오른쪽 → 왼쪽
                answer[bottom][c] = num
                num += 1
            bottom -= 1

        if left <= right:
            for r in range(bottom, top - 1, -1):  # 왼쪽 열: 아래 → 위
                answer[r][left] = num
                num += 1
            left += 1

    return answer
```

- **남은 영역의 경계(`top`, `bottom`, `left`, `right`)를 좁혀 가며** 한 변씩 채운다. 변을 하나 채울 때마다 해당 경계를 안쪽으로 한 칸 옮긴다
- 방향을 바꾸는 시점을 "벽을 만났는가" 대신 "변을 다 채웠는가"로 판단해서, 방향 번호나 `answer[nr][nc] != 0` 검사가 필요 없다
- 아래쪽 행과 왼쪽 열 앞의 `if`는 **한 줄이나 한 열만 남았을 때** 같은 칸을 두 번 채우지 않으려는 것이다. 이 경계 처리가 이 방법의 까다로운 부분이다
- 방법 1이 규칙이 단순해서 더 실수가 적고, 방법 2는 방향을 걷는 대신 범위를 줄이는 관점이라는 점이 다르다
- 세 풀이 모두 n = 1~30 전체에서 결과가 같은지 확인함. n = 4, 5, 1의 출력도 문제와 같다



### 기록

- **방향 이동 문제는 `direct = [(0,1), (1,0), (0,-1), (-1,0)]`와 `d = (d + 1) % 4`로 풀기.** 방향 순서를 문제의 회전 방향(시계/반시계)에 맞춰 나열
- **튜플끼리는 원소별로 더할 수 없다.** `(a, b) + (c, d)`는 이어 붙이기고, 빼기는 에러. `dr, dc = direct[d]`로 풀어서 `r + dr`, `c + dc`
- **두 변수를 한 번에 대입할 땐 쉼표: `r, c = nr, nc`.** `r = nr, c = nc`는 연쇄 대입이라 에러
- **인덱스 범위는 `0 <= x < n`으로 한 번에 쓰기.** 파이썬의 음수 인덱스(`-1`은 마지막)는 범위 검사를 빼먹어도 에러 없이 틀린 칸을 가리킬 수 있다
- 이미 방문한 칸은 **0으로 초기화해 둔 배열의 값이 0이 아닌가**로 판별할 수 있다
- 조건에서 `or`는 앞에서부터 평가되니, **범위 검사를 앞에, 인덱스 접근을 뒤에** 둔다
- 시뮬레이션 문제는 코드를 짜기 전에 작은 입력(4 × 4)을 손으로 따라가 보면 방향이 바뀌는 지점이 보인다. 이전의 "수영장 코스"처럼 방향을 그려서 푸는 문제와 같은 부류
