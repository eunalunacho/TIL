### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/388351)

풀이 시간: 약 25분


### 문제 설명

직원마다 출근 희망 시각이 있고, **평일(월~금)에 희망 시각 + 10분까지** 출근하면 지각이 아니다. 일주일 동안 한 번도 지각하지 않은 직원이 몇 명인지 구하는 문제다. 시각은 `시 × 100 + 분`인 정수로 주어진다 (10시 13분 → 1013). 이벤트 시작 요일(`startday`, 1 = 월 ... 7 = 일)이 주어지고, 토·일의 출근 시각은 무시한다.

- 1 ≤ 직원 수 n ≤ 1,000, 한 직원의 기록은 7일치
- 700 ≤ schedules[i] ≤ 1100, 600 ≤ timelogs[i][j] ≤ 2359
- 시각을 100으로 나눈 나머지(분)는 항상 59 이하

| schedules | startday | result |
| --- | --- | --- |
| [700, 800, 1100] (기록 생략) | 5 | 3 |
| [730, 855, 700, 720] (기록 생략) | 1 | 2 |


### 내 풀이 (10점)

```python
def solution(schedules, timelogs, startday):
    target = [schedule + 10 + 100 -60 if schedule + 10 % 100 >= 60 else schedule + 10 for schedule in schedules]
    answer = len(schedules)

    for i, timelog in enumerate(timelogs):
        for j in range(7):
            if (startday + j) % 7 not in [6, 0]:
                if target[i] - timelog[j] < 0:
                    answer -= 1
                    break

    return answer
```

문제의 예시 2개는 둘 다 통과했지만 채점은 **10 / 100**이었다. 그룹 점수는 그룹 안의 케이스를 전부 통과해야 받는데, #1(n = 1, 월요일, 정각 입력)만 통과했다.

**원인은 첫 줄의 연산자 우선순위 한 곳이다.**

- `schedule + 10 % 100 >= 60`은 `%`가 먼저 계산되어 `schedule + (10 % 100)`, 즉 `schedule + 10 >= 60`이 된다
- `schedule`이 700 이상이라 **항상 참**이고, 그래서 `target`이 언제나 `schedule + 50`이 된다
- 확인: `schedule = 800`이면 `target = 850`이다. 맞는 값은 810이라 **8시 11분~8시 50분에 출근한 지각을 통과시킨다**
- 예시에서는 지각이 그 구간에 없어서 우연히 맞았다. 랜덤 입력 2만 개로 맞는 풀이와 비교하니 약 51%(10,224개)에서 결과가 달랐다

괄호를 붙여서 `(schedule + 10) % 100 >= 60`으로 고치면 전부 맞는다. 아래 `고친 코드`는 이 한 곳만 바꾼 것이다.

```python
def solution(schedules, timelogs, startday):
    target = [schedule + 10 + 100 -60 if (schedule + 10) % 100 >= 60 else schedule + 10 for schedule in schedules]
    answer = len(schedules)

    for i, timelog in enumerate(timelogs):
        for j in range(7):
            if (startday + j) % 7 not in [6, 0]:
                if target[i] - timelog[j] < 0:
                    answer -= 1
                    break

    return answer
```

요일 판별은 처음부터 맞았다. `startday + j`는 `j`일째의 요일 번호이고, 7로 나눈 나머지가 6이면 토요일, 0이면 일요일이다. `startday = 5`(금)이면 `j = 0..6`에서 5, 6(토), 0(일), 1, 2, 3, 4가 나온다.


### 복잡도

**직접 짠 풀이는 O(n²)이 아니라 O(n)이다.**

- 이중 `for`문이라고 해서 O(n²)이 되는 것은 아니고, **두 반복문이 모두 n에 비례할 때** O(n²)이다
- 바깥은 직원 수 n번, 안쪽은 **항상 7번**(요일 수)으로 입력 크기와 상관없는 상수다. 그래서 `n × 7`이고 O(7n) = **O(n)**
- `target`을 만드는 리스트 컴프리헨션도 n번이라 O(n)이다
- 최악의 경우 7 × 1,000 = 7,000번 확인이라 시간은 문제가 되지 않는다. 공간은 `target` 때문에 O(n)

**최적 풀이도 시간은 O(n)이다.** 입력의 모든 값을 최소 한 번은 읽어야 하므로 7n개를 읽는 것보다 빨라질 수 없다. 개선되는 것은 점근 복잡도가 아니라 **상수와 구조**다.

- 한 직원이 지각하면 거기서 멈춘다 (`break`, `all`)
- 평일 인덱스를 한 번만 계산하고 직원마다 재사용한다
- `target` 리스트를 만들지 않아 공간이 O(1)이다 (입력 제외)

| | 시간 | 공간 |
| --- | --- | --- |
| 내 풀이 | O(n) (7n) | O(n) |
| 최적 풀이 | O(n) (최대 5n) | O(1) |

직접 재 보니 n = 1,000에서 내 풀이 약 0.98ms, 아래 최적 풀이 약 1.10ms로 비슷했다. 이 문제에서 최적 풀이의 이점은 속도가 아니라 **시각 계산이 틀릴 수 없는 구조**다.


### 최적 풀이

**시각을 "분 단위 정수"로 바꿔서 비교한다.** `시 × 100 + 분`은 59분 다음이 100이 되는 이상한 수라서 `+ 10`을 하면 올림 처리가 필요하다. 분 단위로 바꾸면 그냥 `+ 10`이고 대소 비교도 그대로 맞다.

```python
def solution(schedules, timelogs, startday):
    def to_min(t):
        return t // 100 * 60 + t % 100            # 1013 → 10 * 60 + 13 = 613

    # 평일인 날의 인덱스 j (startday = 1이 월요일이므로 (startday + j - 1) % 7이 0~4면 월~금)
    weekdays = [j for j in range(7) if (startday + j - 1) % 7 < 5]

    answer = 0
    for schedule, logs in zip(schedules, timelogs):
        limit = to_min(schedule) + 10             # 출근 인정 시각 (분)
        if all(to_min(logs[j]) <= limit for j in weekdays):
            answer += 1                           # 평일에 한 번도 지각하지 않았다

    return answer
```

문제의 예시 1(`startday = 5`, 금요일 시작)로 따라가 보면 이렇다.

- `weekdays`: `j = 0`은 `(5 + 0 - 1) % 7 = 4` → 금요일, `j = 1`은 5 → 토, `j = 2`는 6 → 일, `j = 3`은 0 → 월. 그래서 `weekdays = [0, 3, 4, 5, 6]`
- 두 번째 직원: `schedule = 800`, `limit = 480 + 10 = 490`(8시 10분). 평일 기록 `800, 800(j=3), 759, 810, 809`를 분으로 바꾸면 `480, 480, 479, 490, 489`로 전부 `490` 이하라서 통과
- 세 번째 직원: `schedule = 1100`, `limit = 670`(11시 10분). 평일 기록 `1105, 600, 1059, 1001, 1100` → `665, 360, 659, 601, 660` 전부 통과
- 첫 번째 직원도 통과해서 답은 3

정답 확인: 예시 2개와 랜덤 입력 2만 개(희망 시각 근처 기록 포함)에서 직접 구현한 정답 풀이와 결과가 같다.


### 내가 놓친 것

- **연산자 우선순위: `%`, `//`, `*`는 `+`, `-`보다 먼저 계산된다.** `a + b % c`는 `(a + b) % c`가 아니다. 헷갈리면 괄호를 쓴다. 이번 실수의 전부다
- **예시가 통과해도 맞다는 보장은 없다.** 예시는 버그가 드러나지 않는 입력일 수 있다. 계산 부분은 경계값으로 따로 확인해야 한다 (`800 → 810`, `855 → 905`, `859 → 909`처럼 분이 50 이상일 때 올림이 일어나는 입력)
- **`시 × 100 + 분` 형태의 시각은 그대로 더하면 안 된다.** 분 단위로 바꿔서 계산하면 올림 처리가 필요 없다
- **중첩 `for`가 곧 O(n²)는 아니다.** 안쪽 반복 횟수가 입력과 무관한 상수(7일)이면 O(n)이다
- 채점 결과를 보면 어떤 그룹이 통과했는지로 버그를 좁힐 수 있다. 이번에는 "정각 입력 + 월요일 + n = 1"(#1)만 통과했다. 같은 정각·월요일 조건인 #2(n이 커짐)부터 실패했으니, 요일이나 분 처리보다 **직원이 여러 명일 때 지각이 섞이는 경우**에서 `target` 계산이 틀린다는 신호였다
