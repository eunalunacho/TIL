### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/181858)


### 문제 설명

랜덤으로 서로 다른 k개의 수를 저장한 배열을 만드려고 합니다. 적절한 방법이 떠오르지 않기 때문에 일정한 범위 내에서 무작위로 수를 뽑은 후, 지금까지 나온적이 없는 수이면 배열 맨 뒤에 추가하는 방식으로 만들기로 합니다.

이미 어떤 수가 무작위로 주어질지 알고 있다고 가정하고, 실제 만들어질 길이 k의 배열을 예상해봅시다.

정수 배열 arr가 주어집니다. 문제에서의 무작위의 수는 arr에 저장된 순서대로 주어질 예정이라고 했을 때, 완성될 배열을 return 하는 solution 함수를 완성해 주세요.

단, 완성될 배열의 길이가 k보다 작으면 나머지 값을 전부 -1로 채워서 return 합니다.



### 제한사항

- 1 ≤ arr의 길이 ≤ 100,000
- 0 ≤ arr의 원소 ≤ 100,000
- 1 ≤ k ≤ 1,000



### 입출력 예시

| arr | k | result |
| --- | --- | --- |
| [0, 1, 1, 2, 2, 3] | 3 | [0, 1, 2] |
| [0, 1, 1, 1, 1] | 4 | [0, 1, -1, -1] |



### 내 풀이

```python
def solution(arr, k):
    answer = []
    for i in range(len(arr)):
        if arr[i] not in answer:
            answer.append(arr[i])
        if len(answer) == k:
            break
    while len(answer) < k:
        answer.append(-1)

    return answer
```


### 코드 설명

앞에서부터 보면서 answer에 없는 수만 추가하고, k개가 차면 멈춘다. 끝까지 봤는데 k개가 안 되면 -1로 채운다.

통과는 했지만 `arr[i] not in answer`가 느릴 수 있다. **리스트의 `in`은 처음부터 하나씩 비교**하기 때문에 answer 길이만큼 걸린다.

- 최악의 경우: 서로 다른 수가 999개뿐인데 arr 길이가 100,000이면 k개가 끝내 안 차서 break가 안 걸림
- 그러면 100,000번 × 최대 999번 비교 → 약 10^8번
- 이 경우를 직접 만들어 재 보니 약 387ms 걸렸음. 리스트 `in`의 비교는 파이썬 내부(C)에서 돌아서 일반 for문보다 훨씬 빠르기 때문에 통과는 했지만, 제한이 조금만 커져도 시간 초과가 날 수 있는 구조



### 다른 풀이

```python
def solution(arr, k):
    answer = []
    seen = set()
    for x in arr:
        if x not in seen:
            seen.add(x)
            answer.append(x)
            if len(answer) == k:
                break
    return answer + [-1] * (k - len(answer))
```

- **set의 `in`은 개수와 상관없이 거의 한 번에 확인**함(해시로 위치를 바로 찾음). 순서를 기억하는 answer 리스트와 확인용 set을 같이 씀
- `len(answer) == k` 검사는 새 수를 추가했을 때만 하면 됨
- `[-1] * (k - len(answer))`: 모자란 개수만큼 -1 리스트를 만들어 붙임. 모자라지 않으면 `[-1] * 0`은 `[]`
- 직접 재 보니 최악의 경우 387ms → 1.9ms(약 200배), 랜덤 입력에서도 약 38배 빨랐음

순서를 유지하며 중복을 빼는 한 줄짜리 방법도 있다.

```python
def solution(arr, k):
    unique = list(dict.fromkeys(arr))[:k]
    return unique + [-1] * (k - len(unique))
```

- `dict.fromkeys(arr)`: arr의 원소를 키로 하는 딕셔너리. 키는 중복이 안 되고, 처음 들어온 순서가 유지됨(파이썬 3.7+)
- `set(arr)`은 순서가 보장되지 않아서 이 문제에 쓰면 안 됨
- 다만 k개가 차도 멈추지 않고 arr 전체를 훑음. 직접 재 보니 최악의 경우엔 가장 빨랐지만(1.1ms), 서로 다른 수가 많은 랜덤 입력에선 내 풀이보다도 느렸음(9.7ms). 일찍 멈출 수 있는 문제에서는 set 풀이가 안정적



### 기록

- **"이미 나왔는지" 확인은 리스트 말고 set**. 리스트 `in`은 O(n), set `in`은 O(1)
- 순서가 필요하면 리스트(순서) + set(확인)을 같이 씀
- 순서 유지 중복 제거: `list(dict.fromkeys(arr))`. `set()`은 순서를 섞음
- 모자란 만큼 채우기: `리스트 + [값] * (목표 길이 - len(리스트))`
- 반복 횟수 × 안쪽 비교 횟수로 최악의 경우를 계산해 보기 (10^8 이상이면 위험)
