### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/181831)


### 문제 설명

n × n 크기의 이차원 배열 arr이 매개변수로 주어질 때, arr이 다음을 만족하면 1을 아니라면 0을 return 하는 solution 함수를 작성해 주세요.

- 0 ≤ i, j < n인 정수 i, j에 대하여 arr[i][j] = arr[j][i]



### 제한사항

- 1 ≤ arr의 길이 = arr의 원소의 길이 ≤ 100
- 1 ≤ arr의 원소의 원소 ≤ 1,000
- 모든 arr의 원소의 길이는 같습니다.



### 입출력 예시

| arr | result |
| --- | --- |
| [[5, 192, 33], [192, 72, 95], [33, 95, 999]] | 1 |
| [[19, 498, 258, 587], [63, 93, 7, 754], [258, 7, 1000, 723], [587, 754, 723, 81]] | 0 |

- 첫 번째: 모든 `(i, j)`에서 `arr[i][j] = arr[j][i]`라서 1
- 두 번째: `arr[0][1] = 498`, `arr[1][0] = 63`으로 달라서 0

이 문제는 **대칭 행렬(symmetric matrix)을 판별**하는 문제다. 대각선을 기준으로 위아래가 거울처럼 같다는 뜻이고, 행과 열을 맞바꾼 배열(전치행렬)이 원래 배열과 같다는 말과도 같다.



### 내 풀이

```python
def solution(arr):
    n = len(arr)

    for i in range(n):
        for j in range(n):
            if arr[i][j] != arr[j][i]:
                return 0

    return 1
```


### 코드 설명

모든 `(i, j)` 쌍을 돌면서 **하나라도 다르면 바로 0**, 끝까지 다 돌았다면 모두 같다는 뜻이므로 1을 반환한다.

- 이중 `for`문은 `i`, `j` 모두 `0 ~ n-1`로 돌아서 n² 쌍을 전부 확인한다. `(i, j)`와 `(j, i)`는 서로 다른 반복에서 각각 한 번씩 나온다
- 시간: O(n²). n ≤ 100이라 최대 10,000번이다

**처음엔 문제를 거꾸로 이해했다.**

```python
for i in range(n):
    for j in range(n):
        if arr[i][j] == arr[j][i]:
            return 1
```

- **`i == j`인 칸은 항상 같은 칸끼리 비교**하므로 `arr[0][0] == arr[0][0]`은 무조건 참이다. 첫 반복에서 어떤 배열이든 바로 1이 나온다
- 더 근본적인 문제는 **"모든 쌍이 같아야 한다"를 "하나라도 같으면 끝"으로 구현**한 것이다
- **"모두 만족하는가"를 확인할 때는 반대로, 하나라도 어긋나면 바로 실패를 반환하고 끝까지 돌았을 때만 성공을 반환한다.** "하나라도 만족하는가"를 확인할 때만 하나 찾으면 바로 성공을 반환한다
- 반복 범위(`i`, `j` 모두 `0 ~ n-1`)에 대한 이해는 맞았고, 틀린 건 조건과 `return` 위치였다
- 풀면서 디버깅용 `print`를 넣었는데, 제출 전에는 지워야 한다. 결과에는 영향이 없어도 출력이 쓸데없이 섞인다



### 다른 풀이

내 풀이는 정답이고 충분히 빠르다. 같은 비교를 두 번 하지 않도록 줄이는 방법을 정리했다.

**1. 위쪽 삼각형만 비교하기**

```python
def solution(arr):
    n = len(arr)

    for i in range(n):
        for j in range(i + 1, n):
            if arr[i][j] != arr[j][i]:
                return 0

    return 1
```

- `(i, j)`를 비교하면 `(j, i)`는 같은 비교라서 **`j`를 `i + 1`부터 돌려 대각선 오른쪽 위의 칸만** 확인한다. 반복이 절반 정도로 줄어든다
- `i == j`인 대각선 칸은 자기 자신과 비교하는 것이라 항상 같으므로 빼도 된다 (`i + 1`부터 시작하는 이유)
- 직접 재 보니 100 × 100 대칭 배열(전부 비교해야 하는 경우)에서 내 풀이 약 645µs, 이 풀이 약 296µs로 **약 2배 빨랐다**
- 코드는 `range(n)`을 `range(i + 1, n)`으로 한 곳만 바꾸면 된다. 가독성은 그대로이고 의도도 분명해서 추천하는 풀이

**2. 전치행렬과 비교하기**

```python
def solution(arr):
    return int(arr == [list(row) for row in zip(*arr)])
```

- `zip(*arr)`은 `arr`의 각 행을 인자로 풀어서 같은 위치끼리 묶는다. **각 열이 하나의 튜플이 되어 나오므로 곧 전치행렬**이다

```python
arr = [[1, 2], [3, 4]]
list(zip(*arr))    # [(1, 3), (2, 4)]
```

- `zip`이 튜플로 묶기 때문에 `(1, 3) == [1, 3]`은 `False`다. 그래서 `list(row)`로 리스트로 바꿔서 비교한다
- 리스트끼리 `==`를 하면 원소를 차례로 비교한다. 대칭 행렬이면 전치행렬과 같다는 정의를 그대로 코드로 옮긴 것이다
- 약 317µs로 풀이 1과 비슷하게 빠르다 (비교와 전치 둘 다 파이썬 내부에서 처리되기 때문)
- 짧고 정의와 직접 맞닿는 풀이지만, `zip(*arr)`을 처음 보면 읽기 어렵다

**3. `all`과 제너레이터로 쓰기**

```python
def solution(arr):
    n = len(arr)
    return int(all(arr[i][j] == arr[j][i] for i in range(n) for j in range(i + 1, n)))
```

- `all(...)`은 모든 원소가 참일 때 `True`이고, 거짓을 만나면 거기서 멈춘다. "하나라도 어긋나면 바로 실패"가 한 줄로 표현된다
- 직접 재 보니 약 474µs로 반복문 풀이(풀이 1)보다 느렸다. 줄은 줄었지만 빨라지지는 않는다
- 네 풀이 모두 랜덤 대칭·비대칭 배열 2만 개로 결과가 같은지 확인했고, 문제 예시 2개의 출력도 확인함



### 기록

- **"모든 …가 만족하는가"는 하나라도 어긋나면 즉시 실패 반환, 끝까지 돌면 성공 반환.** 이 틀을 거꾸로 쓰면(같으면 성공 반환) 틀린다. 하나라도 만족하는지는 반대로 쓴다
- **`i == j`인 칸은 자기 자신을 비교하는 것이라 항상 같다.** 조건 확인에서 의미가 없다
- 대칭인지 확인하는 비교는 `(i, j)`와 `(j, i)`가 같은 비교라서 **`j`를 `i + 1`부터 돌려** 절반으로 줄일 수 있다
- 대칭 행렬 = 전치행렬과 같은 행렬. 전치는 `zip(*arr)`로 만들 수 있고, 튜플이 나오므로 `list(row)`로 바꿔서 비교
- `all(조건 for ...)`은 하나라도 거짓이면 멈추는 "모두 만족" 검사. 읽기는 편하지만 속도는 반복문보다 느릴 수 있다
- 문제를 잘못 이해했을 때는 코드를 고치기 전에 **입출력 예시를 손으로 따라가 보며** 조건부터 다시 읽기
- 디버깅용 `print`는 제출 전에 지우기
