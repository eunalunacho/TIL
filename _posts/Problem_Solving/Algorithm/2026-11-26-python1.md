### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/340213)


### 문제 설명

동영상 재생기의 명령(`prev`: 10초 전, `next`: 10초 후)을 차례로 실행한 뒤의 재생 위치를 `"mm:ss"`로 구하는 문제다.

- `prev`: 현재 위치가 10초 미만이면 0분 0초로 이동
- `next`: 남은 시간이 10초 미만이면 영상의 끝(`video_len`)으로 이동
- **오프닝 건너뛰기:** 현재 위치가 `op_start ≤ 위치 ≤ op_end`이면 자동으로 `op_end`로 이동
- 1 ≤ commands의 길이 ≤ 100

| video_len | pos | op_start | op_end | commands | result |
| --- | --- | --- | --- | --- | --- |
| "34:33" | "13:00" | "00:55" | "02:55" | ["next", "prev"] | "13:00" |
| "10:55" | "00:05" | "00:15" | "06:55" | ["prev", "next", "next"] | "06:55" |
| "07:22" | "04:05" | "00:15" | "04:07" | ["next"] | "04:17" |

예시 3은 시작 위치(4분 5초)가 이미 오프닝 구간이라서 **명령을 실행하기 전에** 먼저 오프닝 끝으로 이동한다.


### 내 풀이

```python
def solution(video_len, pos, op_start, op_end, commands):
    v_mm, v_ss = video_len.split(":")
    video_len = int(v_mm) * 60 + int(v_ss)

    s_mm, s_ss = op_start.split(":")
    start_pos = int(s_mm) * 60 + int(s_ss)

    e_mm, e_ss = op_end.split(":")
    end_pos = int(e_mm) * 60 + int(e_ss)

    mm, ss = pos.split(":")
    now_pos = int(mm) * 60 + int(ss)

    for command in commands:
        if now_pos >= start_pos and now_pos <= end_pos:
            now_pos = end_pos

        if command == 'next':
            if now_pos + 10 <= video_len:
                now_pos += 10
            else:
                now_pos = video_len

        elif command == 'prev':
            if now_pos - 10 >= 0:
                now_pos -= 10
            else:
                now_pos = 0

    if now_pos >= start_pos and now_pos <= end_pos:
        now_pos = end_pos

    return f"{(now_pos // 60):02d}:{(now_pos % 60):02d}"
```


### 내 풀이 방식

**시각을 전부 "초"로 바꿔서 정수로 계산하고, 마지막에 `mm:ss` 문자열로 되돌리는 시뮬레이션이다.**

- `"13:00"` 같은 문자열은 `":"`로 나눠 `분 * 60 + 초`로 바꾼다. 초로 바꾸면 `+ 10`, `- 10`, 대소 비교가 그냥 정수 연산이 된다
- 명령마다 **먼저 오프닝 구간인지 확인해서** 구간 안이면 `end_pos`로 보낸다. 그다음 `next`/`prev`를 실행한다
- `next`는 `now_pos + 10`이 영상 길이를 넘으면 `video_len`에서 멈추고, `prev`는 `now_pos - 10`이 0보다 작으면 0에서 멈춘다
- **마지막 명령을 실행한 뒤에도 오프닝 구간인지 한 번 더 확인한다.** 이 부분은 처음에 빠뜨렸다가 추가했다. `prev`/`next`로 이동한 위치가 오프닝 안일 수 있기 때문이다
- 출력은 `:02d`로 두 자리를 맞춘다. `7` → `'07'`

**복잡도**

- 시간 O(m): `commands`의 길이 m(≤ 100)만큼 반복하고, 한 번 반복에서 하는 일은 상수다. 시간 문자열 변환은 길이 5짜리 4개라서 상수
- 공간 O(1): 정수 몇 개만 쓴다 (입력 제외)


### 최적 풀이

**풀이 방식과 복잡도는 그대로 O(m) / O(1)이고, 코드의 반복을 없앤다.** 이 문제는 명령이 최대 100개라서 더 빨라질 여지가 없고, 개선할 수 있는 것은 가독성이다.

```python
def solution(video_len, pos, op_start, op_end, commands):
    def to_sec(t):
        m, s = map(int, t.split(":"))
        return m * 60 + s

    length, start, end = to_sec(video_len), to_sec(op_start), to_sec(op_end)
    now = to_sec(pos)

    def skip(t):
        return end if start <= t <= end else t

    now = skip(now)
    for command in commands:
        if command == "next":
            now = min(now + 10, length)
        else:
            now = max(now - 10, 0)
        now = skip(now)

    m, s = divmod(now, 60)
    return f"{m:02d}:{s:02d}"
```

예시 2(`video_len = "10:55"`, `pos = "00:05"`, 오프닝 `00:15 ~ 06:55`, `["prev", "next", "next"]`)로 따라가면 이렇다.

- 초로 변환: `length = 655`, `start = 15`, `end = 415`, `now = 5`
- 시작 위치 5초는 오프닝(15~415)이 아니라서 `skip`해도 그대로 5
- `prev`: `max(5 - 10, 0) = 0`, `skip(0) = 0`
- `next`: `min(0 + 10, 655) = 10`, `skip(10) = 10` (15초 전이라 오프닝 아님)
- `next`: `min(10 + 10, 655) = 20`, 20은 15~415 안이라 `skip(20) = 415`
- `divmod(415, 60) = (6, 55)`라서 `"06:55"`

**깔끔하게 쓰는 방법**

1. **반복되는 `split` + `int` + `* 60`을 `to_sec` 함수 하나로 묶는다.** 내 풀이는 같은 4줄 패턴을 4번 썼다. `map(int, t.split(":"))`는 `"13:00"`을 `[13, 0]`으로 바꿔서 한 번에 `m, s`로 풀어 준다
2. **`if ... else` 4줄을 `min`/`max` 한 줄로 줄인다.**
   - `next`: `now_pos + 10 <= video_len`이면 `+ 10`, 아니면 `video_len`. 이것은 "`+ 10`과 `video_len` 중 작은 값"이다 → `min(now + 10, length)`
   - `prev`: `now - 10 >= 0`이면 `- 10`, 아니면 0. 이것은 "`- 10`과 0 중 큰 값"이다 → `max(now - 10, 0)`
   - 이렇게 값을 **범위 안에 가두는 것을 클램프(clamp)라고 부른다**
3. **오프닝 확인을 `skip` 함수 하나로 묶고, 명령 직후에 한 번만 확인한다.** 내 풀이는 `for`문 앞에서 한 번, 반복문 뒤에서 한 번, 이렇게 같은 `if`를 두 곳에 썼다. 확인 위치를 "명령을 실행한 직후"로 통일하면 (시작 위치도 반복 전에 한 번 확인) 반복문 안에는 `skip`만 있고, 마지막 확인이 따로 필요 없다
4. **`start <= t <= end`로 쓴다.** `t >= start and t <= end`와 같은 뜻이고 파이썬에서는 비교를 이어서 쓸 수 있다
5. **`divmod(now, 60)`으로 몫과 나머지를 한 번에 구한다.** `now // 60`, `now % 60`을 따로 쓰지 않는다
6. `elif command == 'prev'`를 `else`로 바꿨다. 명령은 `next`와 `prev` 둘뿐이라서 `else`가 같은 뜻이고 안 쓰는 분기가 사라진다

**직접 재 보니** 명령 100개 입력으로 내 풀이는 약 9µs, 위 풀이는 약 17µs였다. `to_sec`, `skip` 같은 함수를 호출하는 비용이 더해져서 오히려 조금 느리다. 둘 다 시간 제한과 무관한 수준이라, 이 풀이의 이점은 속도가 아니라 **반복이 없고 고칠 곳이 한 곳이라는 점**이다.

정답 확인: 문제 예시 3개와 랜덤 입력 3만 개(영상 길이, 오프닝, 시작 위치, 명령 순서 모두 무작위)에서 직접 구현한 기준 풀이와 두 풀이의 결과가 같다.


### 내가 놓친 것

- **시각 문제는 초(또는 분) 단위 정수로 바꿔서 푼다.** 이 부분은 처음부터 잘 했다. 출력은 `divmod`와 `:02d`로 만든다
- **`if a + 10 <= 한계: ... else: 한계`는 `min`, `if a - 10 >= 0: ... else: 0`은 `max`로 쓴다.** 값을 범위 안에 가둘 때 항상 이 형태
- **같은 `if`를 두 곳에 쓰고 있으면 함수로 묶고 호출 위치를 정리한다.** 마지막에 오프닝 확인이 빠지는 실수도 "명령 직후에 `skip`"으로 통일하면 생기지 않는다
- 같은 4줄이 반복되면 함수로 만든다 (`to_sec`)
- `a <= x <= b`처럼 비교를 이어서 쓸 수 있다
- 두 자리 `0` 채우기는 f-string의 `:02d`
- **함수가 많다고 빨라지지는 않는다.** 함수 호출 비용 때문에 약간 느려질 수 있고, 이 문제에서는 상관이 없다
