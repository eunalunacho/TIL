### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/181829)


### 문제 설명

2차원 정수 배열 board와 정수 k가 주어집니다.

i + j <= k를 만족하는 모든 (i, j)에 대한 board[i][j]의 합을 return 하는 solution 함수를 완성해 주세요.



### 제한사항

- 1 ≤ board의 길이 ≤ 100
- 1 ≤ board[i]의 길이 ≤ 100
- 1 ≤ board[i][j] ≤ 10,000
- 모든 board[i]의 길이는 같습니다.
- 0 ≤ k < board의 길이 + board[i]의 길이



### 입출력 예시

| board | k | result |
| --- | --- | --- |
| [[0, 1, 2],[1, 2, 3],[2, 3, 4],[3, 4, 5]] | 2 | 8 |

이 board를 표로 나타내면 다음과 같다.

| i \ j | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 0 | 0 | 1 | 2 |
| 1 | 1 | 2 | 3 |
| 2 | 2 | 3 | 4 |
| 3 | 3 | 4 | 5 |

`i + j <= 2`인 칸은 `(0,0) (0,1) (0,2) (1,0) (1,1) (2,0)`이고, 합은 0 + 1 + 2 + 1 + 2 + 2 = 8이다.



### 내 풀이

```python
def solution(board, k):
    answer = 0

    for i in range(len(board)):
        for j in range(len(board[0])):
            if i + j > k:
                break
            answer += board[i][j]

    return answer
```


### 코드 설명

모든 칸을 돌면서 `i + j`가 `k`를 넘으면 그 행의 나머지를 건너뛰고, 아니면 값을 더한다.

- **`break`가 가능한 이유:** 한 행 안에서 `j`가 커질수록 `i + j`도 커진다. 그래서 `i + j > k`가 되는 순간 그 행의 오른쪽 칸은 전부 조건 밖이다. `break`는 안쪽 `for`문만 끝내고, 바깥 `for`문은 다음 행으로 계속 간다
- `continue`로 썼다면 조건 밖의 칸을 하나씩 다 확인해야 해서 불필요한 반복이 남는다. `break` 덕분에 한 행에서 조건을 처음 넘은 칸까지만 본다
- 예시(k = 2)로 각 행을 따라가면 이렇다.

| i | 확인하는 j | 더하는 값 | 멈추는 지점 |
| --- | --- | --- | --- |
| 0 | 0, 1, 2 | 0 + 1 + 2 = 3 | j = 3은 열이 없어 `range`가 끝남 |
| 1 | 0, 1, 2 | 1 + 2 = 3 | i + j = 3 > 2에서 break |
| 2 | 0, 1 | 2 | i + j = 3 > 2에서 break |
| 3 | 0 | 없음 | i + j = 3 > 2에서 바로 break |

  합계는 3 + 3 + 2 = 8이다
- 시간: 최악의 경우(k가 매우 크면) 모든 칸을 돌아서 O(n × m), 최대 100 × 100 = 10,000번이다



### 다른 풀이

**1. 처음부터 `range`의 끝을 조건에 맞게 줄이기**

```python
def solution(board, k):
    answer = 0
    for i in range(min(len(board), k + 1)):
        for j in range(min(len(board[0]), k - i + 1)):
            answer += board[i][j]
    return answer
```

- `i + j <= k`를 `j <= k - i`로 바꿔서 **`j`가 도는 범위를 미리 `k - i + 1`개로 줄였다.** 조건 검사와 `break`가 필요 없다
- 행도 마찬가지로 `i <= k`인 `0 ~ k`까지만 돌면 된다. `i`가 `k`를 넘으면 `j = 0`이어도 `i + j > k`이기 때문이다
- `min(...)`은 `k`가 커서 범위가 배열을 넘어가지 않게 막는다. 예: 열이 3개인데 `k - i + 1`이 5이면 3까지만 돈다
- 확인용 값: 예시(k = 2)에서 `i = 0`은 `range(min(3, 3))`으로 3칸, `i = 1`은 `range(min(3, 2))`로 2칸, `i = 2`는 `range(min(3, 1))`로 1칸 돈다. 합계 3 + 3 + 2 = 8로 같다
- 불필요한 칸을 아예 보지 않는다. 직접 재 보니 100 × 100 배열에서 내 풀이는 `k = 10`일 때 약 23µs, 이 풀이는 약 12µs, `k = 100`일 때 약 407µs와 약 160µs로 **약 2배 빨랐다**

**2. 조건을 컴프리헨션에 넣고 `sum`으로 더하기**

```python
def solution(board, k):
    return sum(board[i][j]
               for i in range(len(board))
               for j in range(len(board[0]))
               if i + j <= k)
```

- 문제 설명 그대로 "i + j <= k인 모든 (i, j)의 합"을 코드로 옮긴 형태라 읽기 쉽다
- 대신 **`break`가 없어서 모든 칸을 확인한다.** 직접 재 보니 `k = 10`일 때 약 399µs로 내 풀이(약 23µs)보다 **훨씬 느렸다.** 코드가 짧다고 빠른 건 아니다

**3. 행마다 슬라이싱으로 한 번에 더하기**

```python
def solution(board, k):
    return sum(sum(board[i][:k - i + 1]) for i in range(min(len(board), k + 1)))
```

- 각 행에서 **앞쪽 `k - i + 1`칸을 슬라이스로 잘라서 `sum`으로 더한다.** 칸마다 파이썬 코드를 돌리는 대신 내부 함수가 한 번에 처리한다
- `board[i][:k - i + 1]`: 예를 들어 `i = 1`, `k = 2`이면 `board[1][:2]`로 앞의 2칸(`[1, 2]`)을 자른다
- 슬라이스의 끝이 배열 길이보다 커도 에러 없이 있는 만큼만 잘린다 (`[1, 2, 3][:10]`은 `[1, 2, 3]`)
- 직접 재 보니 가장 빨랐다 (`k = 10`에서 약 4µs, `k = 100`에서 약 69µs)
- **행 범위를 `min(len(board), k + 1)`로 제한하는 것이 중요하다.** 이걸 빼고 `i`가 `k`를 넘으면 `k - i + 1`이 0이나 음수가 되는데, 슬라이스에서 음수는 "뒤에서부터 세는" 뜻이라 **엉뚱한 칸이 더해진다** (`[1, 2, 3][:-1]`은 `[1, 2]`). 앞서 본 `[0] * 음수`가 빈 리스트가 되는 것과 달리, 슬라이스의 음수는 조용히 틀린 값을 만든다

네 풀이 모두 랜덤 입력 3만 개(행·열 1~8, k는 가능한 모든 범위)에서 결과가 같은지 확인했고, 예시는 8이 나오는 것을 확인했다.



### 기록

- **`i + j <= k` 같은 조건은 `j <= k - i`로 바꾸면 `range`의 끝을 계산해서 조건 검사 없이 필요한 칸만 돌 수 있다**
- **정렬된/증가하는 값에서 조건을 한 번 넘으면 이후는 모두 넘는다면 `break`.** `break`는 가장 안쪽 반복문만 끝낸다
- 범위가 배열 길이를 넘지 않게 `min(길이, 계산한 끝)`을 쓴다
- **슬라이스의 음수 인덱스는 뒤에서부터 센다.** 끝 값이 음수가 될 수 있으면 슬라이스가 엉뚱한 칸을 가리키므로, 값이 0 이상인지 먼저 보장한다. `[0] * 음수`나 `range(음수)`는 빈 결과인 것과 다르다
- 코드가 짧아도 모든 칸을 확인하면 느릴 수 있다. 컴프리헨션의 `if`는 `break`처럼 중간에 멈추지 못한다
- `i + j`가 같은 칸들은 한 대각선(왼쪽 아래 → 오른쪽 위)에 놓인다. `i + j <= k`는 왼쪽 위 모서리에서 그 대각선까지의 삼각형 영역이다
