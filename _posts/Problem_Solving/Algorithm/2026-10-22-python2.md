### 문제 링크

[문제 바로가기](https://school.programmers.co.kr/learn/courses/30/lessons/181881)


### 문제 설명

정수 배열 arr가 주어집니다. arr의 각 원소에 대해 값이 50보다 크거나 같은 짝수라면 2로 나누고, 50보다 작은 홀수라면 2를 곱하고 다시 1을 더합니다.

이러한 작업을 x번 반복한 결과인 배열을 arr(x)라고 표현했을 때, arr(x) = arr(x + 1)인 x가 항상 존재합니다. 이러한 x 중 가장 작은 값을 return 하는 solution 함수를 완성해 주세요.

단, 두 배열에 대한 "="는 두 배열의 크기가 서로 같으며, 같은 인덱스의 원소가 각각 서로 같음을 의미합니다.



### 제한사항

- 1 ≤ arr의 길이 ≤ 1,000,000
- 1 ≤ arr의 원소의 값 ≤ 100



### 입출력 예시

| arr | result | 
| --- | --- |  
| [1, 2, 3, 100, 99, 98] | 5 |



### 내 풀이

```python
def solution(arr):
    x = 0
    last = []
    
    while arr!=last:
        last = arr.copy()
        for i, num in enumerate(arr):
            if num >= 50 and not num%2:
                arr[i] = num//2
            elif num < 50 and num%2:
                arr[i] = num * 2 + 1
        x += 1

    return x-1
```


### 코드 설명

변환하기 전에 `last`에 지금 배열을 복사해 두고, 변환한 뒤의 arr와 비교해서 같아질 때까지 반복.

`last = arr`로 쓰면 복사가 아니라 같은 리스트를 가리키게 돼서, arr를 바꾸면 last도 같이 바뀜. 그래서 `arr.copy()`로 따로 복사해야 함

arr(x) = arr(x + 1)을 확인하려면 변환을 x + 1번 해야 하므로, 반복이 끝난 뒤 x에서 1을 빼서 return



### 다른 풀이

```python
def solution(arr):
    def change(n):
        if n >= 50 and n % 2 == 0:
            return n // 2
        if n < 50 and n % 2 == 1:
            return n * 2 + 1
        return n

    def count(n):
        c = 0
        while change(n) != n:
            n = change(n)
            c += 1
        return c

    return max(count(n) for n in set(arr))
```

- 각 원소는 다른 원소와 상관없이 혼자 변함. 그래서 배열 전체가 멈추는 횟수 = 가장 늦게 멈추는 원소의 횟수 → 원소마다 멈출 때까지 걸리는 횟수를 세서 max를 구하면 됨
- 같은 값은 걸리는 횟수도 같으므로 `set(arr)`로 중복을 없애면, 길이가 100만이어도 서로 다른 값은 최대 100개(원소 값이 1 ~ 100)라 100개만 계산하면 됨
- 내 풀이는 반복할 때마다 배열 전체를 복사하고, 변환하고, 비교해서 100만 칸을 여러 번 훑음. 다른 풀이는 set을 만들 때 한 번만 훑음
- 길이 100만으로 직접 재 보니 내 풀이 약 0.86초, 다른 풀이 약 0.006초
- 이 풀이에서는 원본 arr를 바꾸지 않음



### 기록

- 배열 전체를 반복 변환하는 문제라도, 각 원소가 서로 영향을 주지 않으면 원소 하나씩 따로 계산할 수 있음
- 원소 값의 범위가 작으면(이 문제는 1 ~ 100) 길이가 아무리 길어도 서로 다른 값은 그 범위만큼밖에 없음 → set으로 중복 제거 후 계산
- 어제 "값의 크기는 복잡도와 상관없다"고 적었는데, 이 문제처럼 값의 범위가 작다는 점은 오히려 계산을 줄이는 힌트가 될 수 있음
- 범위를 작게 줬다면 대부분 이용하라는 신호. "길이는 큰데 값은 작다"는 조합이 보이면, 서로 다른 값이 몇 개 안 된다는 뜻이니 중복 제거(set)나 미리 계산하기를 떠올릴 것



### 다른 문제 풀 때 팁

다른 풀이는 한 번에 떠오르는 게 아니라, 일단 문제 그대로 풀어서 통과한 뒤 아래 질문을 던져서 찾음

1) 제한사항에서 유독 크거나 작은 숫자가 뭘 암시하지?
- 길이가 크면(10만 이상) → 배열 전체를 여러 번 훑으면 느릴 수 있음
- 값의 범위가 작으면(1 ~ 100 등) → 서로 다른 값이 적음 → set으로 중복 제거, 값별로 미리 계산

2) 원소끼리 서로 영향을 주나?
- 각 원소가 자기 값만 보고 변하면(옆 원소나 배열 전체를 안 보면) 원소 하나만 놓고 생각해도 됨
- "배열이 언제 멈추나?" → "원소 하나는 언제 멈추나? 그중 가장 늦은 건?"처럼 문제를 바꿔 볼 것

3) 결과가 같은 계산을 반복하고 있나?
- 이 문제에서 값이 99인 원소가 10만 개면 똑같은 계산을 10만 번 함
- 같은 입력이면 같은 결과가 나오는 계산은 한 번만 하고 재사용
